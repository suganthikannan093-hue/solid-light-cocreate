# Acceptance gates
- A: official SDK project, compiler clean, runtime drawing surface selectable; real browser and IWER input observed.
- B: deterministic masks/intersection; empty/crossing/clipped/noisy input; walkability and stale result tests; exposed instances share authoritative occupancy.
- C: Level 1 actual pointer input, candidate validation, verified path, crossing, reset; varied drawings.
- D: Level 2 short front fails missing X, highlights correct columns, human redraw triggers a new revision, valid candidate crosses; already sufficient input succeeds honestly.
- E: production build, production runtime path, no blocking console errors; emulator hands; invalid/rapid/refresh/resize/visibility/XR-exit recovery; accurate materials; public HTTPS check before P0 release marked complete.
- Hardware: Quest 3/3S hand reliability, legibility, comfort and ≥60 FPS measured on device, never inferred from IWER.
- P1 Level 3: two independent constraints, strategic tradeoff, existing gestures, finale/replay.
- P1 cloud: disabled by default, secure backend, consent, schema/time/rate-limit tests and offline fallback.
